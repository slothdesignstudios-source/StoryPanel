# Smoke-test cost: what one 3-panel strip can cost, and what limits it

Scope: `scripts/live-smoke.py run [--image-provider openai|gemini]`: one 3-panel strip (the prompt is
in the script), cast and script approval, reference-conditioned panels with Anthropic safety and
layout checks and Gemini visual identity QA, one instruction edit, then PDF, PNG and CBZ exports.
Images come from OpenAI (default) or Gemini, fixed for the whole comic. **fal and Voyage are not
called**: exports resample locally (no paid upscaling) and identity QA uses no embeddings.
Traced from the code at this commit. Every number below is regenerated by
`scripts/live-env.sh services/backend/.venv/bin/python scripts/live-smoke.py estimate --markdown`
(simulated call profile from `live-smoke.py run --simulated`, 2026-11-14).

**OpenAI and Gemini prices are UNVERIFIED.** They come from search-result summaries of the official
pricing pages, which are blocked from the build sandbox. Check them on the providers' pages before
approving a paid run. Anthropic prices were read from the official page on 2026-11-12. Neither
estimate is a guaranteed upper bound on charges.

## 1. Four different numbers

| Kind | What it is | OpenAI images | Gemini images |
|---|---|---|---|
| **Estimated cost** | Expected charges for a clean run: the price table, measured prompt sizes and *assumed* output sizes | **≈ USD 3.32** | **≈ USD 1.20** |
| **Application admission limit** | The `--approve-usd` amount, stored as a lifetime `SpendCap` on the smoke user. Before every paid call the app reserves that call's maximum in one serialised transaction. It refuses with `spend_limit_reached` if counted spend plus the reservation would exceed the cap. The per-project ceiling (`SP_SPEND_LIMIT_PROJECT_USD`, default 8) also applies. If retries need more than the cap, the run stops | your amount, at least **USD 4.53** | your amount, at least **USD 1.73** |
| **Provider-enforced spending limit** | Only what you configure at each provider. Anthropic: organisation and workspace monthly spend limits (Console → Settings → Limits). OpenAI: project and organisation budgets and usage limits in the dashboard *(whether they hard-stop requests is unverified)*. Google: Cloud Billing budgets send alerts but **do not cap spending**; Gemini API tiers have rate limits *(unverified)*. None is configured by this repository, and none is documented to stop a request already in flight | none configured | none configured |
| **Charges after a timeout** | A synchronous image call that timed out may still be billed. The app keeps it as an *unresolved* potential charge at its full reservation and never re-sends it automatically | see section 4 | see section 4 |

Suggested approvals for the first live run: **USD 8.00 with OpenAI images** or **USD 4.00 with Gemini
images**. Both cover the clean run and the bad cases in the tables below except "every call fails once".
In that case the cap stops the run before it overspends.

## 3. Constraints applied for this run

| Setting | Why | Where |
|---|---|---|
| `SP_FAL_ENABLED=false`, `SP_VOYAGE_ENABLED=false` | No fal or Voyage account. The adapters stay in the code, but nothing constructs or calls them, and their keys are not read | `config/live-smoke.env`, defaults in `config.py` |
| `SP_EXPORT_UPSCALE=local` | Exports use the native images with local Lanczos resampling and report the effective print DPI. There is no paid upscaling and no "AI upscale" | `config/live-smoke.env` |
| `SP_TEXT_REFUSAL_FALLBACK=false` | With it on, a refused Sonnet 5.5 call can be billed *and* re-run on another model. The reservation holds only one call, so a refusal now ends the run | `config/live-smoke.env` |
| `SP_MAX_CHARACTERS=2` | The prompt names two characters, so reference sheets are capped at 2 | `config/live-smoke.env` |
| SDK retries off (`max_retries=0` for OpenAI, `attempts=1` for Gemini) | Every paid call has exactly one ledger attempt. Retries happen only through the app's own attempt rules: never after an ambiguous timeout, and never on a refusal | `openai_image.py`, `gemini.py` |
| `SP_IMAGE_REQUEST_TIMEOUT_SECONDS=240` | A timed-out call is closed as ambiguous (an unresolved potential charge) and not re-sent. The panel shows a "retry" action, which uses a new attempt | `config/live-smoke.env`, `metering.py` |
| Text reservations from bytes + schema + documented image formula | Reservations stay conservative for non-ASCII text and small images | `pricing.py`, `metering.py` |
| Panel count enforced before panel images are paid for | A script without exactly 3 panels stops the run at the script gate | brief/script validation, `live-smoke.py` |

## 4. What can be billed beyond the cap

1. **Image output larger than the reservation assumption.** Neither OpenAI nor Gemini lets a caller cap
   image output tokens. Each call reserves the price entry's assumed tokens: OpenAI 6,500 image-out
   tokens and 3,000 per input image; Gemini 1,120 image-out, 1,120 per input image and 4,000 text or
   thinking tokens. The settled cost comes from the reported usage. If a call uses more, the overshoot
   is counted afterwards and logged as `provider_estimate_exceeded`, but the cap did not stop it.
2. **Price-table error.** OpenAI and Gemini prices are **unverified**. If a price is wrong, every
   reservation and estimate for that model is wrong by the same factor.
3. **Hidden input overhead.** Text reservations assume API-added input is at most 4,000 tokens per
   call. Output cannot overshoot, because `max_tokens` is a hard cap.

Covered inside the cap (counted at their full reservation until resolved): image or text calls that
time out client-side but may complete server-side; attempts left open by a worker crash; failed
calls (counted as billed by policy). Reservations are serialised, so concurrency cannot overshoot.
OpenAI and Gemini expose no API for looking up a single request's charge afterwards. Resolve an
unresolved attempt with `live-smoke.py reconcile --charges charges.csv`, using the figure from the
provider's usage dashboard. Match by request id where the provider shows one. A timed-out call has
none: match it by time and model, and put `attempt:<attempt_id>` (listed under `still_unresolved`)
in the `request_id` column, with `0` if the dashboard shows no charge.

**For a strict ceiling**, set provider-side limits yourself: an Anthropic workspace spend limit and
an OpenAI project budget for the keys you use, and Gemini API usage monitoring. Google billing
budgets only alert. None of these stops a request that is already running.
