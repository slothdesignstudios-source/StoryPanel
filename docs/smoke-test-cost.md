# Smoke-test cost: what one 3-panel strip can cost, and what limits it

Scope: `scripts/live-smoke.py run [--image-provider openai|gemini]`: one 3-panel strip (the prompt is
in the script), cast and script approval, reference-conditioned panels with Anthropic safety and
layout checks and Gemini visual identity QA, a persistent visual prop (a continuity rule: the keeper
carries a brass lantern), one script edit before approval (three distinct camera shots and a
changed action, re-checked against the Story Bible), one instruction edit, then PDF, PNG and CBZ
exports.
Images come from OpenAI (default) or Gemini, fixed for the whole comic. **fal and Voyage are not
called**: exports resample locally (no paid upscaling) and identity QA uses no embeddings.
Traced from the code at this commit. Every number below is regenerated by
`scripts/live-env.sh services/backend/.venv/bin/python scripts/live-smoke.py estimate --markdown`
(simulated call profile from `live-smoke.py run --simulated`, 2026-11-15; prices verified 2026-11-15).

**Per-token prices were verified on the official pages on 2026-11-15** (excerpts in
`docs/evidence/pricing-2026-11-15/`; Anthropic on 2026-11-12). **Not published, so still assumptions:**
how many tokens `gpt-image-2.5-sunburst` counts per input (reference) image and per output image.
OpenAI says to measure them from each response's usage.

|---|---|---|

| `SP_TEXT_REFUSAL_FALLBACK=false` | With it on, a refused Sonnet 5.5 call can be billed *and* re-run on another model. The reservation holds only one call, so a refusal now ends the run | `config/live-smoke.env` |

| SDK retries off (`max_retries=0` for OpenAI, `attempts=1` for Gemini) | Every paid call has exactly one ledger attempt. Retries happen only through the app's own attempt rules: never after an ambiguous timeout, and never on a refusal | `openai_image.py`, `gemini.py` |
| `SP_IMAGE_REQUEST_TIMEOUT_SECONDS=240` | A timed-out call is closed as ambiguous (an unresolved potential charge) and not re-sent. The panel shows a "retry" action, which uses a new attempt | `config/live-smoke.env`, `metering.py` |
| Text reservations from bytes + schema + documented image formula | Reservations stay conservative for non-ASCII text and small images | `pricing.py`, `metering.py` |
| Panel count enforced before panel images are paid for | A script without exactly 3 panels stops the run at the script gate | brief/script validation, `live-smoke.py` |

## 4. Timeouts, unresolved charges, and what can exceed the cap

**How a paid call is counted** (`providers/metering.py`):

1. **Before it is sent**, the call's full reservation (its maximum under the assumptions) is
   recorded as an attempt and counted against every ceiling. If that would cross the cap, the
   call is not sent.
2. **When it answers with usage**, the count becomes the calculated cost (`calculated`). This can
   be lower or higher than the reservation.
3. **When it times out, the connection drops, or it answers without usage**, the count simply
   *stays at the reservation* (`unresolved`). Nothing is added. It is never re-sent automatically.
   `live-smoke.py reconcile --charges` later replaces it with the figure from the provider's usage
   dashboard. A failed request is also counted at its reservation, by policy
   (`SP_COUNT_FAILED_REQUESTS_AS_BILLED=true`).

So **a timeout's exposure is already inside the cap**, as one reservation. It is not a second
amount on top. What stays open is only *how much* the provider really charged for it.

**What can actually exceed the cap:**

| Source | Why the cap cannot stop it | Size, roughly |
|---|---|---|
| A call that uses more tokens than reserved | The overshoot is known only when the call returns (logged as `provider_estimate_exceeded`). The next reservation then sees the higher total, so the overshoot is bounded by the calls already in flight | OpenAI: input images over 7,000 tokens each, or output over 6,500. Neither count is published for 2.5. Text calls: only API-added input beyond the assumed 4,000 tokens (output is hard-capped by `max_tokens`) |
| An unresolved call whose real charge is above its reservation | Its count stays at the reservation until you import the real figure | Same cause as above: unpublished token counts |
| A wrong price | Every reservation for that model is off by the same factor | Rates were verified on 2026-11-15, so a change after that date |

**Not a source of overrun:** a timeout as such (already counted), retries (each one is a new
reservation checked against the cap), parallel calls (reservations are serialised), and exports
(no paid call).

**Resolving an unresolved attempt:** `live-smoke.py reconcile` lists them (`still_unresolved`).
Import the figure from the provider's usage dashboard with `--charges charges.csv`, matching by
request id where the provider shows one. A timed-out call has no request id. Match it by time and
model, put `attempt:<attempt_id>` in the `request_id` column, and enter `0` if the dashboard shows
no charge.

**For a hard ceiling**, set provider-side limits yourself: an Anthropic workspace spend limit and an
OpenAI project budget for the keys you use. Google billing budgets only alert. None of these stops a
request that is already running.
