# Landing-page hero demo

A 36-second, comic-led walk through StoryPanel's workflow on the landing page (`apps/web/src/app/(site)/page.tsx`).
**It is illustrative.** Every image is a hand-authored development fixture, not StoryPanel output. Nothing is generated, no API is called, and no credits are used. The page says so in the demo's caption and in a "Sample artwork · demo" badge.

## Storyboard (one continuous sequence; objects change roles instead of cutting)

| Time (s) | Scene | What happens | Persistent object |
|---|---|---|---|
| 0–4 | Idea | The idea is typed; "3-panel strip" and "Warm illustrated style" chips; "Create my cast" | Workspace card → **story card** |
| 4–8 | Cast | Keeper and gull cards rise out of the story card; coat and glasses identity highlights; "Approve cast" → "Cast approved" | Cast cards → **margin portraits** |
| 8–12 | Story Bible | Setting, tone, continuity, reveal; continuity and reveal facts highlighted | Bible rows → **script cards** |
| 12–16 | Script | Three cards (wide / medium / close-up); the line "Here you go." is rewritten to "A room with a sea view."; "Saved as version 2"; "Approve and draw" | Script cards → **panel frames** |
| 16–22 | Panels | "Illustrating your story, panel by panel"; soft masked reveal in story order (1, 2, 3) | Art reveals inside the frames |
| 22–26 | Review & edit | Rings on the keeper's glasses in all three panels; the shell is shown only in panel 3; balloon 1 moves off the keeper's face, its tail follows, "Saved" | Lettering settles on the art |
| 26–32 | Read & export | The edited page as a reader view; PDF · PNG · CBZ (labels only; nothing downloads) | Page → **reader/export view** |
| 32–36 | Your comic | "Your idea. Your characters. Your comic.", **Create your comic** (`/new`) and **Replay demo**; holds still | Stable final state |

Story: a lighthouse keeper (yellow raincoat, navy knit cap, round glasses) builds a shivering gull (white body, grey wings, orange beak) a blue shelter; the shell appears only in panel 3.

## Modes

- **Watch** (default): plays once and stops on the finished comic. Play/Pause, Restart and Replay are below the stage. It pauses when less than 35% of the demo is on screen or the tab is hidden, and resumes only if it paused itself. It never loops or restarts on its own.
- **Try it step by step** (Explore): 9 stops with a readable label and instruction, plus Back/Next. Next stays disabled until each stop's action is done: Create my cast → Approve cast → (Bible) → Use the edited line → Approve and draw → (Panels) → move the balloon (drag, **arrow keys**, or "Place it for me") → Read & export → end. Switching from Watch keeps the position (it snaps to the nearest earlier stop). Edits are limited to these authored examples.
- **Reduced motion** (`prefers-reduced-motion: reduce`): starts in Explore on the finished comic, with no autoplay and no animated moves; Back/Next jump between still states.

## Architecture (`apps/web/src/components/hero-demo/`)

| File | Role |
|---|---|
| `timeline.ts` | Pure model: `frame(t, layout, overrides)` returns every element's state (position, size, opacity, scale, text, reveal, tail path). Scenes, Explore stops and gates, balloon validation (`balloonClear`) and the cover-crop mapping (`coverPoint`) live here. There are no timers and no randomness. |
| `stage.tsx` | Semantic HTML plus one SVG overlay for the balloon tails. Each element carries `data-k`; `applyFrame()` writes styles straight to the DOM. |
| `HeroDemo.tsx` | Controller: one `requestAnimationFrame` loop, Watch/Explore state, gates, balloon drag and keys, viewport/tab pausing, and the poster before hydration. React re-renders only on mode or step changes, never per frame. |
| `capture.tsx` + `app/(capture)/demo/capture/page.tsx` | Fixed-size capture page exposing `window.__heroDemo = { seek, ready, duration }`. It is noindex (metadata, `X-Robots-Tag`, robots.txt). |
| `manifest.ts` | Asset manifest (below). |
| `anchors.json` | Art anchor points (heads, glasses, shell) written by the art generator, used for rings and tails. |

Two layouts: landscape stage 640×560 (≥560 px wide) and portrait 360×640 (phones, panels stacked). Each is scaled to the column width with a CSS transform. Watch mode marks the stage `inert`/`aria-hidden`; the figure caption is the concise text description. There is one polite live region (the Explore instruction), which changes only on user action.

**Needed for the final version:** five images generated by StoryPanel for this lighthouse story and approved for public marketing use. They must keep each row's purpose and aspect ratio (cast portraits 5:6, panels 1/2 at 29:20, panel 3 at 56:23), keep the shell out of panels 1–2, and be art without lettering (balloons stay live text). For each, record the project ID and approval. Then:
1. Replace the files, set `status: "approved"` in `manifest.ts`.
2. Re-measure anchors: edit `anchors.json` for heads, glasses and the shell.
3. Run the tests and regenerate videos and posters.

Until all five are approved, keep the "Sample artwork" wording.

## Video capture

```bash
cd apps/web && pnpm build && pnpm start          # production build (the dev server overlays its own badge)
node scripts/capture-hero-demo.mjs --base http://localhost:3000 --out ./hero-demo-video --posters
```

The script seeks the capture route frame by frame at 30 fps (no real-time timers), waits for fonts and images, hides all controls, and pipes PNGs into ffmpeg (H.264, yuv420p, faststart). It writes `hero-demo-landscape.mp4` (1280×1120), `hero-demo-portrait.mp4` (720×1280) and WebP posters of the final frame; `--posters` also refreshes `public/hero-demo/`. It fails if the page requests anything off-origin. A capture takes about 4 minutes on the dev container.

## Local preview

```bash
cd apps/web && pnpm dev          # http://localhost:3000 — the hero works without the API (prices then show as unavailable)
```

or, with the full simulated stack: `scripts/native-services.sh start`, then `SP_LOCAL_S3=moto SP_ALLOW_VOLATILE_STORAGE=1 scripts/native-stack.sh start` (`rm -rf apps/web/.next` first if the web build is stale).

## Verification (2026-11-19)

- Unit (`timeline.test.ts`, 9 tests): determinism, scene order, panels revealed in order and only after script approval, edit text, shell hidden until panel 3, balloon validation, override and tail, cover mapping, manifest honesty.
- e2e (`e2e/hero-demo.spec.ts`, 5 tests):
  - Watch pause holds its place, and the stage is inert.
  - Every Explore gate, including the keyboard balloon edit, and Back keeps progress.
  - End CTA → `/new`.
  - Axe finds no violations in the figure.
  - Reduced motion.
  - Phone order, portrait composition and no horizontal scroll.
  - The capture route is noindex.
  - No `/v1/` or off-origin requests (the page's own server-side `/v1/meta` price fetch is unchanged), and no downloads.
- The full suite: 28 passed, 1 skipped (live Clerk).
- Performance, measured on the production build with Playwright and Chromium, using PerformanceObserver for LCP, layout shift and long tasks, and rAF timestamps for 10 s of playback; mobile ran at 390×844 with 4× CPU throttle:

| Metric | Desktop | Mobile |
|---|---|---|
| LCP | ≈140 ms | ≈210 ms |
| Frame interval p50 / p95 | 16.7 / 16.8 ms | 16.7 / 16.8 ms |
| Frames over 50 ms in 10 s | 0 | 2–3 |
| Demo assets | ≈100 KB (5 SVGs ≈44 KB + one poster) | ≈93 KB |
| JS heap | ≈10 MB | ≈10 MB |

  Layout shift over 37 s of playback is 0.0006 on desktop and 0 on mobile. To get there, cards that resize keep their contents at a fixed size, anchored top-left, and the poster reserves the controls' space. JS is shared with the site (≈770 KB uncompressed in total, including React, Next and Clerk); the demo adds no libraries.
